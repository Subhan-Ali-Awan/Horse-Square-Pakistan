Chapter 2: Front-End Architecture & Page-by-Page Flow (14 Pages)

The client application contains 14 distinct page views organized under React Router DOM v6:

Client Directory Structure:
client/src/
 ├── components/ (Navbar.jsx, Footer.jsx, Modal.jsx, QueryChatModal.jsx)
 ├── context/    (AuthContext.jsx - Global Token & User State)
 └── pages/      (Home, Marketplace, Auction, Breeding, VetDoctor, SellHorse, 
                  Admin, Dashboard, Login, Register, ForgotPassword, RidingSchool, Contact, Blog)

Detailed Flow for All 14 Pages:

  1. Home.jsx: Hero section, featured breed spotlight, quick navigation. Fetches spotlight horses via GET /api/horses?spotlight=true.
  2. Marketplace.jsx: Multi-criteria filter engine (Breed, City, Price slider). Sends dynamic queries to GET /api/horses and renders interactive horse cards with seller contact modals.
  3. Auction.jsx: Displays active live auctions, highest bid, and countdown timer. Accepts user bids via POST /api/auctions/:id/bid after verifying amount > currentBid.
  4. Breeding.jsx: Champion stallion showcase. Submits stud booking requests via POST /api/breeding/request.
  5. VetDoctor.jsx: Equine symptom checker (fever, injury, foot swelling, cough) and city-wise doctor directory. Submits to POST /api/vet/check.
  6. SellHorse.jsx: Seller submission form. Packages horse details and photo files into FormData for submission to POST /api/horses (handled by Multer).
  7. AdminDashboard.jsx: Listing moderation queue (Approve/Reject) and user governance (Active/Block toggle). Protected by adminMiddleware.js.
  8. UserDashboard.jsx: Displays seller's posted listings with approval status badges (Pending, Approved, Rejected, Sold).
  9. Login.jsx & Register.jsx: User authentication. Login saves JWT token to localStorage via AuthContext.jsx.
  10. ForgotPassword.jsx, RidingSchool.jsx, Contact.jsx, Blog.jsx: Supporting views for password resets, academy inquiries, contact messages, and equine health blogs.

Chapter 3: Request Pipeline — Front-End to Back-End API Flow

Below is the complete step-by-step lifecycle of an API request moving from the React UI to the MongoDB database and back:

API Execution Pipeline Trace:
1. [React UI] User submits form (e.g. SellHorse.jsx)
2. [Fetch API] Constructs HTTP request with Authorization: Bearer <token> header
3. [Network] Transmits request to Express server (http://localhost:5000/api/horses)
4. [Express Core] Passes through cors(), express.json(), and morgan() loggers
5. [authMiddleware.js] Extracts JWT token and validates with jwt.verify()
6. [Multer Engine] Intercepts multipart/form-data and writes images to /uploads
7. [Controller] Executes business logic & constructs Mongoose document
8. [MongoDB] Mongoose saves document into horses collection
9. [Express Response] Returns HTTP 201 Created JSON { success: true, horse }
10. [React Component] State updates, triggering Virtual DOM diffing & screen navigation

Authentication Headers & Authorization

All protected backend endpoints check the HTTP Authorization header format: Authorization: Bearer <JWT_TOKEN>. If missing or invalid, authMiddleware.js rejects the request with HTTP 401 Unauthorized.

Error Handling & DB Resilience

All async controllers are wrapped in error handlers. If the primary MongoDB server is unavailable, config/db.js launches an in-memory Mongo server automatically to prevent developer workflow interruption.

Chapter 5: Database Architecture & Entity-Relationship Diagram (ERD)

The MongoDB database utilizes 6 primary collections linked via Mongoose ObjectId references:

Collection Relationships & Foreign Keys:
- User (_id) <------- (postedBy) Horse
- User (_id) <------- (createdBy) Auction
- User (_id) <------- (bidder) Auction.bids[]
- User (_id) <------- (submittedBy) BreedingRequest
- BreedingHorse (_id) <--- (breedingHorse) BreedingRequest
- User (_id) <------- (submittedBy) VetInquiry

Database Indexing Strategy

  • Full-Text Search Index: horseSchema.index({ name: "text", description: "text" }) for keyword searches.
  • Compound Filter Index: horseSchema.index({ breed: 1, price: 1, location: 1 }) for ultra-fast Marketplace queries.

Chapter 7: Real-Time Live Auctions (Socket.io) Architecture

To eliminate manual page refreshing during live equine bidding, Socket.io integration connects buyers directly to a WebSocket server cluster.

WebSocket Real-Time Bidding Sequence:
1. Buyer A places bid -> Socket.emit('bid:place', { auctionId: 101, amount: 550000 })
2. Socket Server validates bid & updates MongoDB Auction document
3. Socket Server broadcasts event -> Socket.broadcast.emit('auction:updated', payload)
4. All connected buyers (Buyer B, C, D) receive event instantly
5. React UI updates bidding panel & countdown timer in real-time without page reload!

Security Hardening Checklist

  • Rate Limiting: Use express-rate-limit to protect auth routes from brute-force attacks.
  • Password Security: Enforce bcryptjs with 10 salt rounds.
  • CORS Hardening: Restrict API calls exclusively to trusted domain origins in production.
